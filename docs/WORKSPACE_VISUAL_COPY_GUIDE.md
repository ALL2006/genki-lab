# GENKI LAB 总工作台视觉与文案规范

## 1. 定位与适用范围

GENKI LAB 是服务多个饮品概念及未来消费品项目的总工作台。青提茉莉是当前案例，不是系统品牌主题。本规范适用于全局导航、运行、数据源、趋势、产品概念、用户验证、模型评测，以及后续新增的系统级页面。

原则是先呈现当前数据、当前状态、可执行动作、证据范围和人工审核结果。视觉不替业务结论背书，产品主题不进入系统导航与运营页面。

## 2. 双层主题

### 2.1 系统主题

系统颜色集中在 `src/styles/tokens.css`：

- 背景使用暖白或冷白；
- 文字使用石墨灰；
- 主操作与选中状态使用低饱和灰蓝；
- 绿色只表示成功；
- 警告、错误分别使用低饱和棕橙和红色；
- 卡片使用 1px 细边框、6—12px 圆角和轻量阴影；
- 不使用渐变、霓虹、玻璃拟态、发光边框或产品素材。

新增系统组件必须优先使用语义令牌，如 `--action`、`--surface-subtle`、`--text-strong`、`--success`，不得新增以具体产品或颜色命名的系统变量。

### 2.2 产品主题

产品主题由 `src/themes/productThemes.ts` 管理，支持：

- `productAccent`
- `productAccentSoft`
- `productTextColor`
- `productImage`

当前映射位于前端展示层，不修改共享数据结构。它只可用于产品详情、内容预览、视频预览和公开测试页的局部容器。组件通过 `product-theme-scope` 和 `--product-*` CSS 变量取得主题，禁止向 `:root`、导航或系统卡片写入产品色。

青提茉莉可使用低饱和浅绿色；未配置产品使用中性灰蓝回退主题。产品图片默认 `null`，且不得出现在运行、数据源、趋势或模型评测页面。

## 3. 界面文案

### 3.1 写作顺序

界面文案按以下优先级组织：

1. 当前数据，例如“新增 12 条资料”；
2. 当前状态，例如“3 条趋势待审核”；
3. 实际动作，例如“运行采集任务”；
4. 证据范围，例如“逐字引文通过，仍需人工确认”；
5. 人工审核情况，例如“修改后通过 2 条”。

按钮使用动词加对象，避免口号和对能力的笼统承诺。模型输出必须同时标记来源、DEMO/LIVE 状态与人工审核门槛。

### 3.2 禁用表达

界面不得使用以下表达：

- AI驱动
- 智能赋能
- 一键洞察
- 创新引擎驱动
- 开启创新之旅
- 无限可能
- AI为你
- 智能驾驶舱
- 数据赋能未来

替换示例：

| 不使用 | 使用 |
| --- | --- |
| AI驱动智能分析 | 分析 12 条新增资料 |
| 一键生成创新方案 | 生成 3 款候选概念 |
| AI发现消费趋势 | 模型标记 3 条待审核趋势 |
| 开启智能采集 | 运行采集任务 |
| 赋能产品创新 | 将已确认趋势转为候选产品 |

“AI”可以在接口、Provider、原始字段名或技术文档中用于准确说明技术来源，但不作为面向用户的价值口号。

## 4. 页面名称

界面统一使用以下名称，旧路由继续保留：

| 路由 | 界面名称 |
| --- | --- |
| `/dashboard` | 运行 |
| `/data-sources` | 数据源 |
| `/trends` | 趋势 |
| `/concepts` | 产品概念 |
| `/validation` | 用户验证 |
| `/evaluation` | 模型评测 |
| `/content` | 内容资产 |

## 5. 状态与可访问性

- Loading、Empty、Error 使用系统主题，不使用产品主题；
- 成功状态可使用绿色，普通可用状态不等于成功；
- DEMO 使用警告色并明确写出 DEMO，不能用颜色替代文字；
- 焦点环使用灰蓝令牌，保持键盘可见性；
- 移动端沿用同一名称、状态含义与信息层级；
- 产品色必须保证正文对比度，无法确认时使用 `productTextColor` 或系统正文色。

## 6. 当前实现边界

本次只调整前端令牌、活动页面文案和产品主题映射，未改变路由、API、业务功能或共享数据结构。旧原型样式仍保留兼容别名，后续完整视觉重构时再删除未使用组件与兼容层。
