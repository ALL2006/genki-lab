# 3—5 分钟 Demo 脚本

## 0:00—0:25｜开场与真实性边界

打开运行看板。说明 GENKI LAB 是“人机共决策的自动化闭环”。指出红色 `DEMO DATA`：第一阶段用模拟采集、模拟 AI 和模拟反馈验证系统链路，不把它们描述为真实市场结果。

## 0:25—1:05｜采集、去重与日志

进入数据源中心，说明只有 MockCollector 已启用。点击“手动运行”，首次展示 fetched=5、new=5。再次运行，展示 duplicate=5、new=0。返回看板展示 JobRun、durationMs、成功率与错误区域。

## 1:05—2:00｜AI 趋势与证据追溯

点击“运行分析”，进入趋势雷达。展开一条趋势：展示 RawItem 编号、原始标题、链接、支持判断的原文、置信度和风险。强调 AI 默认 pending；现场点击“确认”，并演示另一条设为“需修订”。

## 2:00—2:50｜三款候选与人工入围

进入产品工坊，点击“生成 3 款候选”。对比口味、人群、场景、卖点、风险、来源趋势和 AI 评分。输入人工评分，选择一款入围。强调未人工选择不会进入视频阶段。

## 2:50—3:25｜现有视频能力

切到已准备的青提茉莉广告样片，说明其由独立 Remotion 工程配置驱动，并经过素材预检、字体门禁、静帧和人工审核；本阶段系统尚未自动生成视频配置，也没有修改该工程。

## 3:25—4:10｜反馈回流与 V2

进入验证与迭代，说明当前是模拟反馈。展示购买意愿、拒绝原因、V1/V2、保留/修改/淘汰。指出第二阶段会接真实问卷并保留原始反馈，再由 AI 归纳、人工确认。

## 4:10—4:40｜价值与落地

回到看板：展示任务耗时、成功率、失败日志和可替换适配器。总结真实价值实验将比较人工流程与 AI 辅助流程的时间、修改率、成功率和质量，不使用虚构效率数字。

## 现场兜底

- API 不通：先打开 `/api/health`，再检查 8787 端口。
- 没有趋势：先 collect，再 analyze。
- 无法生成产品：至少确认一条趋势。
- 重置数据：备份后删除本地 `data/mock-db.json`，重启 API；不要在正式数据环境执行。
